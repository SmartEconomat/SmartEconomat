1. Introducción

Este documento describe lo que el usuario puede hacer con el instalador de SmartEconomat según la implementación real del repositorio: un ejecutable Electron (proceso principal + renderer React) que orquesta Docker, certificados, red local y ciclo de vida del stack, y un instalador NSIS generado por electron-builder que despliega los artefactos en disco.

Criterio de verdad: si una captura parece sugerir un comportamiento distinto al del código, prevalece el código. Las figuras de este documento son apoyo visual; los textos citan rutas, canales IPC y configuraciones verificables en el árbol fuente.

2. Descripción general de la aplicación

El producto se articula en dos capas complementarias:

  • Instalador NSIS (Windows): definido en ElectronInstaller/package.json bajo build.nsis. Copia binarios y recursos, permite elegir idioma, ruta de instalación y accesos directos.
  • Aplicación Electron «SmartEconomat»: tras la instalación, el ejecutable arranca el proceso principal (src/main/index.ts), carga el preload seguro (src/preload/index.ts) y el renderer React (src/renderer/app/App.tsx). El usuario recorre un asistente por pasos (useInstallerFlow en src/renderer/hooks/use-installer-flow.ts) y, una vez desplegado el stack, dispone de un panel de control con operaciones sobre contenedores, backups y diagnóstico.

El frontend web de gestión del economato (React en frontend/smart-economat-frontend) no forma parte del ejecutable del instalador; se empaqueta en la imagen Docker del frontend y se sirve cuando el stack está en marcha. La guía del instalador se centra en Electron; la identidad visual de este HTML replica la paleta MUI del instalador y del frontend (primary.main ≈ #dc004e, secondary.main ≈ #0a6151).

3. Requisitos previos

El código del paso «preflight» valida el entorno antes de permitir continuar el asistente. Entre las comprobaciones implementadas en preflight.service.ts destacan:

  • Docker Engine y Docker Compose operativos (estados OK, WARN o BLOCKER según resultado de comandos).
  • Comprobaciones de sistema operativo, espacio en disco, privilegios y conectividad coherente con el runtime elegido.
  • En Windows, la aplicación empaquetada exige elevación a administrador para gestionar Docker, WSL y certificados (véase sección 5).

El dominio local por defecto del asistente es smarteconomat.app (campo localHost en la configuración por defecto de use-installer-flow.ts), con puertos HTTP/HTTPS configurables (httpPort / httpsPort).

8. IPC, consola de depuración y aplicación web

8.1 Puente de contexto aislado (preload)

El preload expone window.smartEconomat con métodos que delegan en ipcRenderer.invoke y suscripciones por evento. Resumen de grupos en src/shared/ipc-channels.ts:

Área Operaciones expuestas al renderer
Instalador Preflight, auto-reparación, liberar puerto ocupado, iniciar instalación, elegir ficheros, probar SMTP, estado y progreso (installer:*).
Runtime Arranque / parada / reinicio del stack, salud, logs en vivo, exportar logs visibles, poda segura o agresiva (con confirmación), desinstalación, backup y restore, diagnósticos, certificado, autostart Docker, watchdog, supervisor, reinicio Docker Desktop (runtime:*).
Depuración Registro de logs del renderer hacia el main, stream y lectura de entradas de depuración cuando el modo debug está habilitado (debug:*).

8.2 Ventana «Debug Console»

Si el modo debug está activo en el proceso principal, puede abrirse la ventana secundaria cargando /debug (src/main/index.ts).

8.3 Frontend web (post-instalación)

Con el stack en marcha, la aplicación de gestión se sirve desde Docker; tema y paleta alineados con frontend/smart-economat-frontend/src/utils/theme/themes.ts (MUI, primario ≈ #dc004e).

9. Casos de uso reales

  • Instalación inicial en Windows: ejecutar el NSIS, aceptar UAC, completar el asistente Electron hasta deploy y abrir el panel para verificar salud.
  • Reinstalación: si getInstallerBootState informa instalación existente, el modo pasa a reinstall en configuración.
  • Operación silenciosa desde inicio de sesión: arranque con --background y uso de la bandeja para abrir /control cuando sea necesario.
  • Resolución de puertos bloqueados: desde preflight, closeBusyPort invoca releaseBusyPort en el main.
  • Copia de seguridad antes de actualizar: backup manual desde el panel (backupNow) a la carpeta persistida o elegida por el usuario.

10. Errores comunes (detectables en código)

  • Puente no disponible: mensaje «No se pudo conectar con el bridge de Electron…» si tras reintentos no existe window.smartEconomat.
  • Preflight con bloqueantes: el hook agrega un resumen de hasta tres chequeos en estado BLOCKER al mensaje de error.
  • Timeout de instalación: superados 12 minutos sin respuesta exitosa de startInstallation, se muestra error de tiempo excedido (el usuario puede reintentar sin cerrar la app).
  • Elevación denegada: si el usuario cancela UAC o falla Start-Process -Verb RunAs, se informa y la aplicación termina.
  • Docker lento o sin daemon: textos orientativos en evaluateDockerChecks y funciones relacionadas (timeouts, pipe de Docker Desktop, etc.).

11. Conclusión

El instalador SmartEconomat combina un empaquetado NSIS estándar de Windows con una aplicación Electron que guía el despliegue Docker y el endurecimiento local mediante un flujo de pasos y un panel operativo persistente.
